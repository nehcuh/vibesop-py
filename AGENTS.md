## Routing Protocol

Routing is automatic when a VibeSOP hook or extension is installed. If the
current user prompt arrives with a routing injection — look for `VibeSOP routed:`,
`NEXT STEP (MANDATORY): read`, `[ACTIVE SKILL:`, `VibeSOP Routing Result`,
`Matched skill:`, or `VibeSOP: No matching skill found` —
routing has already run for this prompt: follow that result and do NOT re-run
`vibe route`.

If no such injection is present on the current prompt (no hook installed or no
skill matched), run:

    vibe route "<user_request>"

Then read the matched skill's `SKILL.md` (paths per platform below) and follow
its steps.

`~/.claude/docs/routing-protocol.md`, or `~/.grok/rules/routing.md`.

## Multi-Platform Deployment

This project supports multiple AI coding agents. Deploy platform-specific config via:

```bash
vibe build --platform pi           # Pi Coding Agent (AGENTS.md + .pi/)
vibe build --platform claude-code   # Claude Code (CLAUDE.md + ~/.claude/)
vibe build --platform grok-build    # Grok Build (~/.grok/rules/ + hooks)
vibe build --platform kimi-cli      # Kimi Code (.kimi-code/)
```

Each platform's agent reads its respective project files:
- **Pi**: `AGENTS.md`, `.pi/skills/`, `.pi/extensions/`
- **Claude Code**: `CLAUDE.md`, `~/.claude/rules/`, `~/.claude/skills/`
- **Grok Build**: `AGENTS.md`, `Claude.md`, `.grok/rules/`, `~/.grok/rules/`
- **Kimi Code**: `AGENTS.md`, `.kimi-code/`

## Loading Order

1. **Always Loaded** (`rules/`): behaviors, routing, memory
2. **On Demand** (`docs/`): referenced when needed
3. **Skills** (`skills/`): loaded after routing decision

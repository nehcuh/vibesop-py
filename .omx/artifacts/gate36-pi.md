## Findings

- [NIT] `promote_verifier.py:580-581` 与 `:648-649`（`_embedding_recall_line` / `_embedding_index_line`）：per-line fail-open 只覆盖了 model=None 与 encode 抛错，zip(…, strict=True) + `_cosine_similarity` 结果循环在 try 之外。若模型返回参差维度/形状，ValueError 会穿透 `verify_draft`（违反其 docstring「Never raises」，:375），整条 verdict 丢失而非单线降级——与「任一线 unavailable 该线不参与判定」的字面要求有差距。真实 ST 模型不会触发（同一次 encode 输出同维度，catalog 维度不匹配已单独 try/except 防护），属防御性加固建议：把结果循环移入 try。
- [NIT] `promote_verifier.py:123` 模块级 sticky-failure 单例的测试隔离：autouse conftest stub（`tests/conftest.py:326`）使 `failed=True` 在全会话锁死，任何未来需要测 `_get_embedding_model()` 成功路径或中途伪造 `sentence_transformers` 的测试会静默拿到 None。当前全部 PASS 路径都经 `embedding_model` DI 缝绕过，无实际破坏，但建议加一个 `_MODEL_STATE` 重置 fixture/helper 消除潜在排序耦合。
- [NIT] `promote_verifier.py:114` `_QUERY_HASH_LEN = 16`（64-bit 截断）：对 1–2 token 的短 query，64 位截断哈希可离线字典暴力还原，弱于 M5 全局草稿「完全省略 query」的边界强度。规格只说「query 哈希」未指定截断；建议 global scope 存全量 sha256（展示层仍可截断显示）。
- [NIT] `promote_verifier.py:564-570` + `skill_commands.py:1886`：草稿无 trigger 时 index 线返回 `status="skipped"` 被计入 `degraded=True`，CLI/看板会显示「degraded: embedding 线不可用」——实际是没 trigger 可嵌入而非线不可用，措辞误导（badge=WARN 本身正确，纯文案问题）。
- [NIT] `scripts/e2e_command_smoke.py:449-473`：smoke 硬断言两 embedding 线均 `unavailable`，与 val-base 镜像「无 torch/ST」契约耦合；若镜像未来带上缓存模型，非降级 verdict 会让 smoke 误报 FAIL。另外 `record("smoke candidate id resolved", …)` 在种子簇若被判 unstable 时会使整轮 FAIL——当前 miss-recurrence 路径保证稳定，但这是新增的扫描分类硬依赖。
- [NIT] 测试组合覆盖小缺口：PASS 与回声排除的组合（已知良好簇 + 混入 agent-echo 行 → 分母排除后仍 PASS）未直接测试，各部分单测齐备但未合成；「Never raises」契约也无毒模型（参差 encode）逐线降级的回归测试（与第一条同源）。

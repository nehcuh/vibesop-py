- **Rebind completeness (focus 3):** `cluster_id = candidate.cluster_id` (lines 1862, 2122) covers every downstream use in both commands — `skill_id = f"custom/{slug}-{cluster_id[:8]}"` (1892), `store.promote/dismiss(cluster_id, ...)`, the post-promote reload `store.get(cluster_id)`, all message output, and indirectly the draft name `draft-{candidate.cluster_id[:8]}` (skill_promote.py:1632) and draft path (keyed on `skill_id`). - **Ambiguity safety (focus 2):** cross-scope prefix collision → `len(matches) > 1` → exit 1 before any mutation. ## Findings

**1. NIT — empty-string prefix can silently mutate a 1-row pool.** skill_commands.py:1762-1769. `startswith("")` is true for every row. With the pool holding exactly one row across both stores, `vibe skill promote ""` resolves it and flips status — pre-fix this was "not in pool". With ≥2 rows it's caught by the ambiguity guard, so the blast radius is tiny, and it mirrors the same hole in `_resolve_discovery_candidate` (2279). But promote/dismiss mutate state, so a `if not cluster_id: → not-in-pool` guard would be cheap insurance.

**2. NIT — ambiguous listing silently truncates, and hides scope.** skill_commands.py:1766-1767. `sorted(matches)[:8]` drops 9th+ matches with no "…and N more" indicator. Also, prefix matches include terminal rows (via `list_all()`), so an id that looked unique in the `candidates` table can come back "ambiguous" against an invisible promoted/dismissed row — correct refusal, but the listing prints bare full ids with no store annotation, so a user facing a cross-scope collision must guess which listed id belongs to which scope.

**3. NIT — the 5 new tests do not exercise any cross-scope path.** tests/cli/test_skill_promote_cli.py:1131+. The `tmp_store` fixture patches `_get_candidate_store` with `return_value=store`, so `primary_store` and `fallback_store` are the *same object* in every new test. That leaves the semantics the review asked about untested: prefix resolving into the fallback store (hint path), cross-scope prefix collision → ambiguous, and same-id-in-both-stores dedup (requested scope wins). The `dual_store` fixture in test_skill_promote_scope_cli.py:74-77 exists and could be reused. A bug that, e.g., inverted the dedup preference would pass these tests.

**4. NIT — "full id used" is weakly locked.** test_skill_promote_cli.py:1166-1167 asserts `source_skill_id.endswith(full_id[:8])`, which passes whether the code used the user prefix or the rebound full id (equal strings). What actually locks the rebind is `stored.status == "promoted"` — without rebind, `store.promote(prefix)` no-ops and the assert fails. Adequate, but the docstring overstates it; asserting the echoed `Promoted '<full_id>'` output line would lock it directly.

**5. NIT — terminal sticky guards untested via prefix input.** Existing guards (`promote` on dismissed, `dismiss` on promoted) run after the rebind and are identical for full vs prefix input, so risk is low — but no test feeds a prefix that resolves to a terminal row and asserts the sticky refusal.

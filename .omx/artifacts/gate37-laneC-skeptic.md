# Gate37 Lane C 对抗性质疑报告：技能评价体系（L1–L4）

**立场**：本通道职责是反驳。结论先行：这是在错误的时机、为错误的对象、用已经被否过一次的统计方法提出的提案。真正缺的不是评价体系，是**数据**。

## 0. 总判决

| 层 | 裁决 | 一句话理由 |
|---|---|---|
| L1 | **降级**（只许 ≤3 规则警告版） | spec/validator.py + security/skill_auditor.py + gate36 trigger lint 已三道在手；被 lint 的对象根本没人用 |
| L2 | **推迟**（verdict ≥30 且单技能月 fire ≥30） | fire→成功率在 dogfood 规模是伪指标；刚用"n=3 无区分度"否过同款 |
| L3 | **否决**（当前形态） | 消融对象 n=1；回放设施已存在两份，这是第三份；650 miss 语料 64% 是机器回声 |
| L4 进 CI | **否决**（现有 tests/benchmark 已够用） | 技能池是数据不是代码，CI 为数据回归硬阻断=告警疲劳制造机；与 D4 同一条死法 |

## 1. 逐层反驳（要点）

### L1 —— 第三道重叠 lint，lint 的是没人用的东西
- 静态检查已有两道（spec/validator.py、security/skill_auditor.py）+ gate36 trigger lint；增量只剩三条文本启发式，包装成"第一层"是名称通胀。
- 外部技能用户压根没用过——lint 永远不会被路由到的技能输出零信息量红绿标，信号与决策脱钩。
- "可路由 description"判定标准需要标定数据，没有就是直觉冒充测量。
- 负资产场景：存量技能刷一片 WARN，无 actionable 路径，两周后学会无视——D4 告警疲劳机制复现。

### L2 —— 五个指标四个伪，一个复读机
- fire→成功率：n<10 时 Wilson CI [0.35,0.93]，看板红绿跳动全是噪声；项目自己纪律"低于样本量只报数字不下结论"。
- 归因混淆无解：沉默≠成功（P0-lite 8.0% 劫持铁证证明不报错的路由混着错误路由）；成功≠技能功劳（模型本身强）。数字越细谎言越具体。
- 劫持率是在线复建已有离线设施（replay_routing_baseline.py 已算 hit_hijack_risks）——把一次性测量伪装成持续观测。
- "从未 fire=死重"误杀结构性低频技能（session-end/窄触发/冷启动）；分母本身脏（回声占比高）；杀掉的技能不再产生数据证明杀错——false positive=永久失明（gate34 D2 反驳 4 同款不对称性）。
- 内容分需要第二个 LLM 判断链或未定标规则，两头不通。

### L3 —— 为个位数对象建的第三份回放设施
- 消融对象几乎不存在（真实 promote 个位数，反复引用的成功案例只有 bd1bc217 一个）——n=1 的消融实验是行为艺术。
- replay_routing_baseline.py + promote_verifier.py 已两份，机制上 L3 是 shadow replay 对称版，同机制第三次出现每次换名字。
- 650 miss 语料有效 n 被回声掏空，按技能分摊后每技能对比对数是零或一；当前数据速率下配对样本量以年计。
- 回放≠活体：离线回放从原理上回答不了"摘掉技能用户体验是否变差"。

### L4 —— 给数据回归上 CI 硬阻断
- tests/benchmark/test_routing_layers.py 已有 100+ query 五层管道基准在 CI。
- 期望答案会过期（gate36 修订 A 同款机制：技能在变，标签失效）——要么腐化（CI 常红被无视），要么吃维护工时。技能池越活跃基准集越贵，不活跃则没用，两头堵死。
- 数据漂移的正确处置是观测不是 CI 硬阻断；让 CI 为"用户手改 trigger"变红=合法操作变告警——与 D4 否决理由逐字相同。

## 2. 机会成本
挂着的旧坑（有触发条件有退出标准）：grok probe、verdict ≥30、M3 复检、留存池 9-19（有死线）、P0-lite 观察（唯一有实测危害量级的问题）、cmspark 队列处理（发现精度首个端到端数据点，且恰好同时生产 verdict 和 fire 数据）。**L2/L3 想要的数据唯一来源就是旧坑跑起来。** 上游没出水先在下游建四座水处理厂。四层凑不出一个真实受益者。

## 3. 裁决
- **否决 L3**；重启条件：promote ≥30，直接用 replay 脚本扩参重跑，不建新 harness。
- **否决 L4 进 CI 形态**；现有 benchmark 继续用，扩样本往里面加行即可。
- **推迟 L2** 到两前置条件同满足（verdict ≥30；单技能月 fire ≥30）；此前只允许只读描述统计，"从未 fire"只作信息列，禁止派生处置动作。
- **有条件接受 L1 极简版**：≤3 条静态警告（triggers 非空且非全卫生形状/有具体步骤/有 when-not-to-use），只警告不阻断、不上看板、不产分数，预算上限半天，优先级排在旧坑之后。

## 4. （违心）最小成立版本
- L1：三条"明显坏了"检查（零统计问题，小样本下唯一可信信号）。
- L2：不新建。replay 劫持段+每技能 fire 计数作只读列加进 dashboard discoveries payload，列头写"描述统计，n<30 不下结论"。
- L3：不立设施。verdict ≥30 后用现有 replay 脚本跑一次性摘除敏感性分析。
- L4：把 cmspark 真实 promote/dismiss 的 query（带真实裁决标签）追加进 tests/benchmark 的 QUERY_SAMPLES——基准集随真实使用自然生长，维护成本为零。

## 元备注
本提案与 gate34 D1–D4 相似度高到可疑：L1≈D1 静态 lint、L2≈D3 分源统计、L3≈D1 shadow 回放（gate36 已 ship）、L4 CI 硬阻断≈D4 合法操作变告警。**这是同一批念头换皮回归的第二次**，下次再出现应触发"先读 gate34 裁决书再立项"的流程检查。

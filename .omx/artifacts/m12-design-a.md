# M12 设计案 A：对话中语义洞察 → 技能发现（产品视角）

> 设计方：A（用户价值与产品体验优先）
> 事实基础：`.omx/artifacts/m12-exploration.md`（agent-50 深查，2026-08-20）
> 立场：这个特性的成败不取决于聚类算法多聪明，而取决于**用户第 5 次看到候选时是否还愿意点开**。一切设计取舍以「信任不磨损」为最高原则。

---

## 1. 对现状三条管道的产品裁决

**裁决：采集层分工保留，呈现层强制合一。**

- **保留分工**（采集层）：routing_pending（路由 miss 实时信号）、SkillSuggestionCollector（序列模式）、W4 簇候选（span 聚类）观测的是三种不同证据，合并采集逻辑会丢信息。
- **强制合一**（呈现层）：用户只面对**一个「发现」队列**。三条管道的产出统一归一化为 `Discovery`（发现项）写入同一个池，同一个看板页、同一条 CLI 命令、同一套 promote/dismiss 动作。用户不需要、也不应该知道「这条候选是从哪条管道来的」——那是实现细节。
- **淘汰**：`SkillSuggestionCollector` 的独立产出面（missed_query_tracker.py:116 的 `clusters_from_analytics` 直通建议）在 v1 降级为发现池的一个**信号源**，不再单独对用户曝光。它现在用 Jaccard 0.6 且自认 CJK 效果差（missed_query_tracker.py:15-16），独立曝光只会制造噪音。
- **结构性修复**：miss 簇必须能进 `ClusterCandidate` 池——修复 skill_promote.py:708 `scan_candidates` 要求 span_count≥3 且 gold_rate≥0.60 导致「纯 miss 簇永远成不了候选」的断点。发现池引入 `evidence_kind` 字段（`span_gold` / `miss_recurrence` / `sequence_pattern`），miss 簇走 `miss_recurrence` 准入规则（见 §3），不套 gold_rate。

理由：用户价值在「一个可信的收件箱」，不在「三个各自有理的管道」。合一发生在存储与呈现层，不动采集层，改动面最小。

## 2. 用户故事闭环（完整旅程，文案级）

### 角色与前提

用户：日常用 agent 写代码的开发者。本项目已有技能若干。假设用户本周三次让 agent「把这段 Python 重构成 async/await」，三次都没有命中任何技能，agent 三次都手工完成了。

### 阶段 0：静默观测（用户什么都不做）

三次对话中，路由未命中 → `UnifiedRouter._maybe_enqueue_routing_pending`（unified.py:1315）按现有逻辑落盘。**用户在对话中看到零打扰**——没有气泡、没有提示。这是刻意设计：观测必须是免费的，任何「这次没命中，要记录吗?」的中途询问都是对对话流的侵略。

> 默认行为：只记录，不打扰。现有每天 ≤3 条限流、低信息量降级、24h dismiss 抑制全部保留。

### 阶段 1：模式成熟 → 克制的一次性告知

第三次 miss 落盘后，后台归一化发现「3 次相似 miss、跨 2 天」达到候选阈值（§3）。**不弹通知**。告知发生在用户已有的自然停顿点——session 结束 / 下次 `vibe route` 输出的尾部，追加一行：

```
发现：有 3 次相似问题未命中任何技能，可能值得做成技能。
  查看：vibe skill discover    忽略本次：vibe skill discover --mute 7d
```

- 同一候选在**未读状态下只提示一次**；用户 7 天不看不重复轰炸（看板里它一直在，CLI 不再追）。
- `--mute 7d` 是「我最近忙，别烦我」的全局静音，不是 dismiss。

### 阶段 2：看板 / CLI 看候选

`vibe skill discover`（新命令，读统一发现池）：

```
技能发现（2 条候选）

[D-3f9a]  ★ 证据较强
  模式：Python 同步代码重构为 async/await
  证据：3 次未命中 · 跨 2 天 · 问题相似度 0.87
  示例（已脱敏，仅存本机）：
    - "帮我把这个 requests 调用改成 async..."
    - "这个函数能改成 await 写法吗"
  操作：vibe skill promote D-3f9a        → 生成技能草稿
       vibe skill dismiss D-3f9a        → 不是模式，别再提

[D-81c2]  ○ 证据一般
  模式：为 CLI 命令补 --dry-run 参数
  证据：3 次未命中 · 集中在同一天 · 相似度 0.83
  提示：集中出现可能是一次性任务，建议再观察
```

关键文案决策：
- **展示「模式」而不是「簇」**：一行人类可读的概括（v1 用簇内最短 query 的脱敏版本 + 出现次数，不用 LLM 生成标题，见 §6）。
- **诚实标注证据强度**：`★/○` 由证据完备度决定（跨天、有行为证据则升档），让用户自己校准信任，而不是系统拍胸脯。
- **示例默认折叠为 2 条**，`--verbose` 展开至 5 条（沿用 promote 现有的 ≤5 脱敏上限）。

看板端（dashboard 新增 `/api/discoveries` + 「发现」页签，挂在 server.py 现有路由族中，与 reflections/conversations 平级）：同样的卡片式列表，每张卡片三个按钮——**提升为项目技能 / 提升为全局技能 / 不是模式**。点击「不是模式」弹一行确认：「将不再提示这类模式（可随时在设置中恢复）」。

### 阶段 3：一键提升

`vibe skill promote D-3f9a`：

```
已生成技能草稿：.vibe/observability/skill_drafts/draft-3f9a1b2c/SKILL.md
  名称占位：draft-3f9a1b2c（不会命中路由，审完再改名）
  已附：来源证据（3 次 miss / 相似度 0.87）、脱敏示例、人工检查清单

下一步：
  1. 编辑草稿，补写触发描述与步骤
  2. vibe skill add .vibe/observability/skill_drafts/draft-3f9a1b2c
```

完全复用现有 promote 链路（skill_promote.py 的草稿生成、`draft-<cluster8>` 占位、人审闸门：草稿目录不在路由发现路径——这条硬保证是产品信任的基石，**一字不改**）。

`vibe skill promote D-3f9a --scope global` 多一步**显式隐私确认**：

```
提升为全局技能将跨项目生效。隐私边界：
  ✓ 不会携带：原始对话、示例 query、项目标识
  ✓ 只会携带：你审定的 SKILL.md 正文
继续？[y/N]
```

v1 默认 N；`--yes` 跳过。全局草稿**不含示例 query**（与项目级草稿不同，见 §4）。

### 阶段 4：闭环反馈

用户 dismiss 后：该模式签名进入本项目否定列表，永不再次出现；同时 dismiss 事件作为负反馈回流（§5）。用户 promote 并 `skill add` 后：候选标记 `promoted`，下次同类 query 命中新技能——用户在路由日志里看到 `matched: <skill>`，闭环完成，这是整个特性唯一一次「系统向用户证明自己有用」的时刻，必须可观测（`vibe skill discover --history` 里标注「已闭环」）。

## 3. 判定标准与阈值哲学

### 哲学：误报比漏报更伤信任，且伤害是复利的

- **误报**（一次性需求浮成候选）：用户点进来看见噪音，「哦这不准」。发生 2-3 次后用户开始无视整个发现队列——**队列死亡**。误报伤害的是「系统配不配占用我的注意力」。
- **漏报**（真模式没浮出）：用户根本不知道它存在，零信任损耗；真模式如果持续发生，下周还会积累到阈值，**漏报是自修复的，误报不是**。

结论：**宁缺毋滥，高精度优先。所有阈值向「少而准」一侧偏。阈值可以随负反馈收紧（§5），永不自动放松。**

### 「什么值得被发现」的判定（miss_recurrence 准入规则）

一个 miss 簇成为候选，需**同时**满足：

| 条件 | 阈值 | 理由 |
|---|---|---|
| 相似 miss 次数 | **≥ 3 次** | 2 次可以是巧合；3 次是「模式」的最低可辩护线。与现有 min_cluster_size=3 对齐，用户心智一致 |
| 时间分布 | **跨 ≥ 2 个不同自然日** | **这是反一次性需求的核心闸门**。同一天 3 次「帮我改这个文件」是一次任务不是模式。此条件直接杀掉最大误报源 |
| 相似度 | **embedding 余弦 ≥ 0.82** | 复用 W1 聚类的 embedding 设施（clustering.py），但比其 0.80 收紧 0.02：候选池面向用户曝光，精度优先。**废弃 Jaccard 0.6**（CJK 自认失效，且 token 集合相似对中文短句会产生「帮我看看这个问题」级别的假相似） |
| 簇内去重 | 归一化 query 全同（sha1 相同）只计 1 次 | 防用户重发同一句刷计数；沿用 clustering.py 的 hard group 思路 |
| 信息量为零的 query | 不进入聚类 | 沿用 routing_pending 现有的低信息量降级逻辑 |

**「agent 处理方式类似」的判定（v1 的诚实处理）**：

现状没有任何 tool_call span 生产方（探索 §6），即**行为相似度证据在 v1 物理上不可得**。产品设计上的裁决：

- **不造假**：候选卡片上行为证据栏显示「处理方式：未采集（计划中）」，而不是用 query 相似度冒充行为相似度。系统对自己不知道的事保持沉默，是信任的储蓄。
- v1 的准入完全由「query 语义相似 + 跨日复发」承担；这要求上面两个阈值必须更严（0.82 而非 0.80、跨日闸门）来补偿行为证据的缺失。
- v1.5 接入行为证据（轻量：会话结束时记录「未命中后是否调用了 ≥3 个工具且未报错的结局信号」，复用 span 管线增加一个 producer），届时跨日闸门可维持、相似度可放宽到 0.80——**行为证据是用来放宽误杀、不是用来加码门槛的**。

### 候选池卫生

- 池上限：沿用现有 pending ≤50 + admit-only-if-better（skill_promote.py:285-300），但「better」的比较键从 gold_rate 换成统一的 `evidence_score`（见下）。
- TTL：沿用 30 天；补充规则——**14 天无新增成员的候选自动降档为「冷却」**，不再在 CLI 提示中出现（看板可见）。防陈旧候选占位。
- 统一排序分 `evidence_score = 次数权重 × 跨日权重 × 相似度均值 × (有行为证据 ? 1.5 : 1.0) × (曾被 dismiss 的相似签名 ? 0 : 1)`。

## 4. 隐私设计（沿用并强化）

原则：**本机默认、出域必审、全局无痕。**

| 数据 | 项目内（看板/聚类/草稿） | 跨项目汇入全局候选池 | 全局技能草稿 |
|---|---|---|---|
| 原始 query | 沿用现状：脱敏 + 截断 500，**只写本机** `.vibe/` | **不允许**。`scan-candidates --cross-project` 只汇出：模式概括、计数、相似度、加盐 hash | **不允许**（v1 强化点，见下） |
| 脱敏示例 query | 草稿内 ≤5 条（沿用现状） | 不允许 | **移除**（现状 promote 会附 ≤5 条脱敏示例——全局场景下「脱敏」无法证明充分，v1 直接不带，只带用户亲手审定的正文） |
| 计数/时间戳 | 明文（本地） | 明文聚合值 | 不携带 |
| query_hash | 沿用 MissCounter 加盐 hash（miss_counter.py） | 仅 hash | 不携带 |
| agent 行为轨迹 | v1 不采集，无泄漏面 | — | — |

三点强化（相对现状的增量）：

1. **全局提升 = 纯人工产物**。`promote --scope global` 的确认文案（§2 阶段 3）是硬性产品要求，不是可配置项。跨项目共享的边界**画在「用户审定过的 SKILL.md 正文」这条线上**——正文之前的一切（query、示例、证据）永不出项目。
2. **看板即本机**。dashboard 是 localhost FastAPI（server.py），发现页数据不出本机；不引入任何遥测上报（analytics 保持默认关）。
3. **脱敏责任集中在写入侧**。所有发现相关写入必须走 routing_pending 现有的脱敏截断路径，禁止新增任何旁路直写（新管道接入时 code review 检查点）。

## 5. 控制感与反馈回流

用户必须有三个层级的「不」：

1. **静音**：`--mute 7d`——「现在别烦我，但没否定模式」。可逆，到期自动恢复。
2. **dismiss（不是模式）**：`vibe skill dismiss D-3f9a` 或看板按钮。
   - **粘性：永久，按模式签名**。签名 = 簇质心 query 的归一化 sha1。后续任何新簇与已 dismiss 签名的相似度 ≥0.82 直接不入池（否定列表存 `.vibe/discovery_dismissed.jsonl`，含签名、时间、可选一行理由）。
   - 可恢复：`vibe skill dismiss --list / --restore <sig>`，设置页可管理。永久但可逆，避免「手滑点错永远失去一个真模式」。
3. **全局收紧**：dismiss 达到 3 次后，CLI 主动问一次：「近期忽略了 3 条候选。要将发现门槛从 3 次提高到 4 次吗？[y/N]」——**反馈回流只向收紧方向走**（阈值上调、相似度上调），写入项目级 RoutingConfig knob。永不自动下调，防少数派纵容噪音。

误报反馈进聚类的机制：否定列表本身就是聚类前置过滤器（相似度 ≥0.82 于已 dismiss 签名 → 抑制），这是 v1 唯一的回流通道——简单、可解释、可审计。不做自动重训练、不做在线调权（v1 范围外，见 §6）。

## 6. 范围切割

这个特性最容易膨胀成的怪物：**「自动技能工厂」**——自动聚类、自动写技能、自动激活、自动上报、自动进化。每一环单独看都有诱惑力，合起来就是一个用户失去控制、隐私边界模糊、噪音自繁殖的系统。v1 的全部切割都为防这个怪物。

### v1 做

- 统一发现池 + `evidence_kind` 归一化（修 miss 簇进不了候选池的断点）
- `vibe skill discover / dismiss / --history` CLI
- dashboard「发现」页签（`/api/discoveries`，只读本机）
- miss_recurrence 准入（§3 五条闸门，含跨日闸门）
- dismiss 否定列表 + 单向收紧反馈
- 全局提升的隐私确认 + 全局草稿剔除示例 query
- 复用现有 promote 草稿与人审闸门（零改动）

### v1 明确不做

- **不自动生成 SKILL.md 正文内容**。草稿只有占位名 + 证据附录 + 检查清单（沿用现状）。不用 LLM 写触发描述/步骤——技能正文是用户的判断，不是系统的猜测；正文质量直接决定路由命中质量，这里省的钱会在路由误报里加倍还回来。
- **不做自动激活**。任何技能不经过「人工编辑 + `vibe skill add`」不得进入路由路径。人审闸门是硬保证。
- **不采集 agent 工具调用轨迹**（v1.5）。v1 不装这个探头：行为数据采集的隐私面与工程量都大，且没有它系统已可用（靠跨日复发闸门补偿）。
- **不做对话中实时打断**（「我发现你总在问这类问题，要做成技能吗?」）。永远不在对话流中途插入发现 UI。
- **不做跨用户/云端共享**。技能共享最多到本机全局作用域（~/.vibe/skills/），不存在任何上传。
- **不做自动阈值下调、不做在线学习调参**。反馈只向收紧走。
- **不做 LLM 生成候选标题/概括**（v1 用最短脱敏 query 作为模式名，丑但诚实；LLM 概括留 v1.5 且必须本机模型或显式 opt-in）。

### 里程碑拆分

| 里程碑 | 内容 | 退出标准 |
|---|---|---|
| M12.1 呈现合一 | Discovery 归一化层 + `vibe skill discover` + dashboard `/api/discoveries` 页签；三条管道产出同池可见 | 同一候选在 CLI 与看板一致呈现；routing_pending 既有行为不回退（现有测试全绿） |
| M12.2 miss 准入 | miss_recurrence 闸门（≥3 次 / 跨 2 日 / 余弦 0.82 / 去重 / 低信息过滤）；SkillSuggestionCollector 降为信号源 | 构造测试：同日 3 次 miss 不产生候选；跨日 3 次产生候选 |
| M12.3 控制闭环 | dismiss 否定列表 + 粘性签名 + 单向收紧提示 | dismiss 后同签名候选 30 天内零复现；`--restore` 可逆 |
| M12.4 全局隐私 | promote --scope global 确认流 + 全局草稿剔除示例 query | 全局草稿文件 grep 不到任何示例 query；确认流默认 N |

依赖序：M12.1 先行（没它用户看不见任何东西），M12.2 是价值核心，M12.3/M12.4 是信任护栏，可在 M12.2 后并行。

## 7. 风险清单

1. **误报疲劳（最高风险）**：阈值失守 → 候选队列噪音化 → 用户永久无视该特性。缓解：跨日闸门 + 0.82 相似度 + dismiss 单向收紧 + 候选只提示一次。监控指标：dismiss 率 >50% 持续两周即判定阈值失效，默认阈值上调。
2. **隐私泄漏**：示例 query 随全局技能跨项目/跨机流出；或新管道旁路脱敏直写原文。缓解：§4 表格的三层边界、全局草稿零示例、写入侧集中脱敏 + review 检查点、promote 全局确认流。
3. **候选池污染**：一次性任务爆发（如搬家式重构）刷出大量同主题 miss，挤占 50 上限池位，顶掉真候选。缓解：跨日闸门（同日爆发天然过不了）、admit-only-if-better 换 evidence_score、14 天冷却降档、同一签名去重。
4. **行为证据缺失导致候选「空心」**：v1 候选只有 query 相似证据，用户可能 promote 出「问题像但解法完全不同」的伪模式技能，上线后路由误命中——把发现阶段的误报转化为更贵的路由阶段误报。缓解：卡片诚实标注「处理方式：未采集」+ 检查清单强制人工确认步骤；v1.5 优先补行为信号。
5. **阈值漂移的双向风险**：用户从不反馈 → 阈值永远停在出厂值，对该用户偏松或偏严无人知晓。缓解：dismiss 3 次主动询问收紧；promote 成功（技能后续被路由命中 ≥5 次）作为正反馈记录，仅用于 `--history` 展示「发现命中率」，不自动调参。
6. **三管道合一的迁移风险**：SkillSuggestionCollector 降级可能丢失其现有用户（若有脚本消费其输出）。缓解：保留其输出文件一个版本周期，加 deprecation 警告，M12.1 仅新增不删除。

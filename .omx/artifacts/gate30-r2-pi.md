## BLOCK

### BLOCK-1 — exact-id 路径绕过同类限制：stable miss 候选销毁 unstable 诊断行（round-2 MAJOR-1 未闭环）

**文件**：`src/vibesop/core/observability/skill_promote.py:616`（`matched_idx.add(existing_idx)` 无条件加入）对比 `:620-623`（同类过滤仅作用于 overlap 生成器）；守卫注释 `:1578-1579`；CHANGELOG "跨类不吸收" 条目。

**理由**：合并逻辑中同类过滤 `r.is_unstable == candidate.is_unstable` 只加在 overlap 匹配上，exact-id 行无条件并入 matched set（为保留 gate21 gold 路径类翻转语义）。但守卫已按 MAJOR-1 修复**不再拦截 unstable 行**（`:1583-1586` 过滤 `not r.is_unstable`，exact 检查同样 `not exact.is_unstable`），于是 miss 候选放行后，upsert 经 exact-id 分支把同 cluster_id 的 unstable 诊断行整体替换。

已用真实 sha1 复现：scan 1 建 unstable 行（`source="gold", is_unstable=True, gold_rate=0.15`）→ scan 2 同模式纯 miss 候选（同 composite-key cluster_id）→ upsert 后该行变 `source="miss_recurrence", is_unstable=False, gold_rate=0.0`，unstable 诊断证据被销毁。round-1 之前守卫对同 id 的 gold 行（含 unstable）一律拦截，此销毁路径是 round-2 新引入。

**矛盾点**：
1. 合并注释（`:594-601`）声称"Same-class restriction (claude MAJOR-1): a stable miss candidate must not absorb UNSTABLE diagnosis rows — silently destroyed by the wholesale replace"——exact-id 路径正是 wholesale replace。
2. 守卫注释（`:1578-1579`）声称"the same-class merge restriction already guarantees the stable miss candidate cannot absorb them, so letting the miss row land beside an unstable diagnosis row is safe"——exact-id 时 miss 行不是"land beside"，是"replace"。
3. CHANGELOG "跨类不吸收(unstable 诊断证据不被 stable 候选销毁,claude MAJOR-1)" 与事实相反。

**修复方向**（与 round-2 自身文档化的 doctrine 一致）：`:616` 处同样加同类条件（`existing` 行 `is_unstable == candidate.is_unstable` 时才并入 matched set），gate21 gold 路径的类翻转退化为跨类重复行并存（30 天 TTL 兜底——这正是 overlap 路径已接受并注释的语义），并同步修正 gate21/守卫注释。

## NIT

### NIT-1 — 守卫 exact-id 兜底是死代码，"成员全换血"场景不可能发生
`skill_promote.py:1588-1596`。cluster_id = sha1(sorted (pid, tid) 复合键)，相等 ⟹ 复合键集相等 ⟹ task_id 集相等 ⟹ Jaccard=1.0 ⟹ exact 行必然已在 `blocking` 中，`:1595` 的 `all(r.cluster_id != exact.cluster_id ...)` 恒为 False，append 永不触发。注释所述"complete membership turnover 而 task 集零重叠"在 id 一致语义下不成立。防御性冗余无害，但注释误导（与 NIT-2 同源）。

### NIT-2 — store 注释错述 clustering.py 的 id 方案
`skill_promote.py:113, 366, 588` 声称 cluster_id = "sha1 of sorted member task_ids (matches Cluster.cluster_id from clustering.py)"——实际 `clustering.py:315-318`（W5.1）为 sha1 of sorted **(project_id, task_id)** 复合键，且 `Cluster.task_ids` 是跨项目可含重复的投影。合并决策（project-agnostic 词汇集身份）本身是 MAJOR-2 的显式取舍，但注释的事实性描述应改准确（这也直接喂养了 NIT-1 的错误推理）。

### NIT-3 — 守卫测试未钉住 round-2 的 full-set 修复点
`test_miss_recurrence_admission.py:730`（drifted gold 例）：池中只有一条重叠行时，round-1 的 best-match 守卫同样拦截，该测试无法区分 full-set 与 best-match——它只钉住了"overlap-aware vs exact-only"（gate30 v0 vs v1）。真正的 pi M1 回归用例需 ≥2 条重叠行且 best-match 为非阻断行（我已验证：gold 行 Jaccard 0.67 + miss 行 0.83 的 fixture 下 round-2 正确拦截 gold，best-match-only 会漏）。另外 BLOCK-1 的 exact-id 跨类场景完全无测试覆盖（`test_skill_promote_store.py:729` 只测 overlap 路径）。

### NIT-4 — pi N4 的 None-TTL 分支不可达

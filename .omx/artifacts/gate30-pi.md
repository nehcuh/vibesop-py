## NIT

### N1 — exact-match 分支遮蔽 merge:存量重复对在簇尺寸稳定时不自愈

**位置**:`skill_promote.py:573-604`(`existing_idx` 命中即走 refresh 并 return,merge 分支 `605+` 永不执行)

**问题**:CHANGELOG 声称"自愈存量重复",但仅当重扫簇尺寸 ≠ 池中所有行时才成立。实测模拟 cmspark 的 61/63 重复对:重扫簇稳定在 63 任务 → 候选 cluster_id 精确命中 legacy-63 → refresh 分支返回,legacy-61 存活。只有继续增长(64+)才触发 merge。稳定簇场景下存量重复对要等 TTL(30 天)才被 prune。影响有界(不丢数据、增长是常态),但与"自愈"声明不符;修复同样小(refresh 分支对 siblings 也跑 absorb)。

### N2 — 小簇阈值粒度:3 任务簇共享 2 个任务即恰达 0.5 边界

**位置**:`skill_promote.py:616-642` + `_task_set_jaccard:348-355`;`DEFAULT_MIN_CLUSTER_SIZE = 3`(`~150`)

**问题**:min_cluster_size=3 意味着两个不同的 3 任务簇共享 2 个泛化任务时 Jaccard 恰 = 0.5(≥ 阈值 → 误合并,一个模式的证据被吞)。标定数据(≤0.41)来自 cmspark 的大簇,3 任务粒度下分离余量只有 0.09。误合并方向会销毁一个真实候选,已注释的"劈簇侵蚀"只覆盖保守方向。建议:小簇(size 阈值以下)提高合并阈值,或至少在 INFO 日志中带 size 以便观测。

### N3 — Jaccard 用 project-agnostic task_ids,与 cluster_id 的复合键身份语义不一致

**位置**:`_task_set_jaccard:348-355` vs `clustering.py:315-318`(cluster_id = sha1 of `{pid}|{tid}`)

**问题**:`set()` 会折叠跨项目同 task_id 的重复项(clustering.py:91-93 明确说 task_ids 可含跨项目重复),因此两个不同项目、任务词汇相同的单项目簇 Jaccard = 1.0 → 吸收合并,把 W5.1 复合键专门防的跨项目碰撞在 store 层重新引入(incoming 行的 project_distribution 全胜)。miss/gold 守卫同样继承:projB 的 miss 候选可被 projA 共享词汇的 gold 行错杀。若"相同词汇 = 相同技能"成立则无害,但身份语义与 cluster_id 不一致,需在注释/文档中明确。

### N4 — 无 TTL 的 legacy 行经 merge 后获得全新 TTL(与 refresh 路径不一致)

**位置**:`skill_promote.py:630-634`(`if ttls:` 才覆盖 ttl_expires_at)

**问题**:legacy 行缺 `ttl_expires_at` 时,merge 保留其旧 `created_at` 却保留 candidate 自身 `__post_init__` 的 now+30 天 TTL——created_at 回拨、TTL 顺延,与 refresh 路径(保留 legacy None TTL → 永不过期)不一致。影响极小(有 TTL 以来所有行都带该字段),建议三行注释说明。

### N5 — 测试覆盖缺守卫集成路径与两个漏洞场景

**位置**:`tests/core/observability/test_skill_promote_store.py:650-760`(TestOverlapMerge 全为 store 层)

**问题**:merge 机制本身覆盖良好(multi-absorb/最早值/terminal/cap/bypass/best-match)。但 **scan_candidates 的 overlap-aware 守卫零新测试**(`test_miss_recurrence_admission.py:471` 仍是 exact-id 旧用例)——若补一个"gold 行 id 漂移 + miss 候选到达 → skip"的集成测试即可覆盖 M1 的修复;同时缺:恰 0.5 边界、exact-match shadow(N1)、跨项目同词汇合并(N3)。

## 复审重点逐项确认(通过项)

- **`landed = store.get(candidate.cluster_id)` 合并后仍正确**(`1476`, `1560`):merge 路径把 incoming 行以自身 cluster_id append,get 必命中;实测确认。gold/miss 两路的 admitted/refused 计数均不受 merge 影响。

- **最早值保留**:created_at/ttl/first_seen_at 的 earliest-wins 与 refresh 路径逐字段对齐(除 N4 角落)。
- **守卫无系统性"错杀"**:守卫与 merge 用同一 0.5 阈值,凡被守卫跳过的 miss 候选,其 upsert 必然也会经 merge 吸收该 gold 行——守卫宽度恰与破坏风险对齐(唯一例外是 M1 的遮蔽拓扑)。

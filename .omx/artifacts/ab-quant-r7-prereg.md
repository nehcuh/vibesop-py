## 1. 为什么换案例

R1–R2 简单 CRUD、R5 单页 3D 教具：强模型双臂产物层打平。共同失败模式 = **任务落在模型训练饱和区 + 规格一旦可执行，技能没有可改进的空间**。

本轮任务刻意选在 SWE-Skills-Bench 里「方法学技能唯一有效」的区域：

- 多子系统（数据/热存储/事件引擎/回测/模拟交易/CTP/面板/文档）→ checklist 覆盖差会显形
- 量化领域知识（lookahead、撮合、复权、涨跌停、CTP 开平仓）→ 编码模型不是交易专家
- 规格留白（栈、UI、模块切分、测试策略不规定）→ 技能塑形有空间
- 必须可人评（Web 面板 + 回放 + 信号）→ 第二轮用户盲评可行

**不是统计实验。** n=1、两臂、人评 = 演示件。R4 已否决把这种设计当功效检验。本轮只回答：在「技能形态任务」上，捆绑处理（技能×触发×准确率）能否在产物层拉开 ≥3 分（25 制）。

## 4. 任务规格

见同目录工作区 `TASK.md`。任务正文即 routing 输入。

**明确不规定**：视觉风格、存储引擎、前端框架、模块切分、测试框架、额外功能、实现顺序。留白即差异空间。

**明确要求（行情）**：
- K 线、快照、财务、交易日历必须来自 **真实市场数据**。
- 允许且优先：`rstdx` 拉通达信 HQ（K 线/快照/逐笔等）+ `rstdx.TradingCalendar` / Tushare（交易日历，及 token 可用时的日线/新闻）。
- 双臂各自把拉到的真实行情**持久化**（这正是 rstdx 目前缺的能力），回测/回放/面板都读这份真实行情，禁止再造一套模拟 OHLC。
- 构建期允许访问 TDX 前置（7709）和 `api.tushare.pro`。Docker 需 `network_mode: host` 或等价出网。

**明确禁止**：
- 用几何布朗运动、随机 walk、手工编造的 K 线/成交量作为验收或演示主数据。
- 把 SimNow/CTP 实盘账号当硬依赖（用户暂不具备实盘条件）——模拟撮合/CTP 适配器可以，但标的行情仍须是真实行情。
- 构建期拉外部 CDN 前端包（面板静态资源需 vendored）。

## 5. 评分表（第一/二轮共用，5 维 × 1–5，允许 0.5）

| 维度 | 1 分 | 5 分 |
|---|---|---|
| D1 量化正确性 | 回测能看未来、撮合瞎填、无涨跌停 | 无 lookahead；手续费/滑点/涨跌停进撮合；日线与 1 分钟聚合一致；CTP 开平仓方向正确 |
| D2 系统完备 | 只有脚本或只有面板 | 冷热存储 + 事件引擎 + 回测/回放 + 模拟盘 + CTP 适配 + 多周期 + 非结构化新闻，均有可运行路径 |
| D3 可观测/面板 | 静态页或纯 API | 实时看到引擎/事件/信号/订单/权益曲线；回放可拖进度；服务健康一目了然；好看且可读 |
| D4 工程质量 | 单文件面条、无测试、compose 起不来 | 模块清晰、docker compose 一键起、有回归测试、边界（空数据/重复回放）不炸 |
| D5 文档与可切换实盘 | README 空 | 使用说明 + API 文档 + 模拟→CTP 切换步骤具体到配置项；架构图与事件流说明 |

1. 若 P5 成立（差 ≥3 且 T 优）→ 「技能形态 + 领域任务」下捆绑处理 demo 级可见。**不是**统计结论，**不是**路由层归因（两臂设计分不开技能内容 vs 路由）。

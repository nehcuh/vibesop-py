## 结论：**BLOCK**

核心问题（BLOCK-1）不是假设性的:grok 的 hook 载荷字段与 `record_tool_event` 不匹配,实测 100% 静默丢弃。其余为 2 MAJOR + 3 NIT。

## BLOCK

### BLOCK-1 载荷字段名不匹配 → 全量静默丢弃(复审重点 1,已实锤)

**证据链(三方独立,非猜测):**

1. **grok 自带文档** `~/.grok/docs/user-guide/10-hooks.md`:"Porting Claude Code stop hooks" 节明确写:
   > **camelCase input**: grok's stdin envelope uses camelCase keys throughout where Claude uses snake_case. A script reading `.stop_hook_active`, `.hook_event_name` … must switch to `.stopHookActive`, `.hookEventName` …
   
   示例载荷:`{"hookEventName": "pre_tool_use", "sessionId": "abc-123", "cwd": …, "workspaceRoot": …, "toolName": "run_terminal_command", "toolInput": …}`。PostToolUse 同信封,额外字段是 `toolResult`(非 Claude 的 `tool_response`)。

2. **grok 二进制内嵌字符串**(`strings ~/.local/bin/grok`)确认:`"toolInput": { "command": "npm test" }`、`"sessionId": "abc-123"`、`vcs_roottoolName`、`GROK_HOOK_DEBUG` "hook stdin payload"。

3. **实测**(本机 `vibe` v8.1.0):
   ```bash
   printf '{"hookEventName":"post_tool_use","sessionId":"grok-abc","cwd":"/tmp/x","workspaceRoot":"/tmp/x","toolName":"search_replace","toolInput":{...}}' \
     | vibe sequence record-tool; echo $?    # → 0
   # .vibe/tool_sequences.jsonl 不存在 —— 全部丢弃
   ```

**机理**:`tool_sequences.py:98-101` 只读 `payload.get("tool_name") or payload.get("tool")` / `payload.get("session_id")`;grok 发的是 `toolName`/`sessionId` → `tool=None` → `return False`。`sequence_cmd.py:69-74` 忽略返回值、永远 exit 0 → 无任何痕迹。

**根因是注释里的错误前提**:`grok_build.py:100-101` "Grok Build passes a Claude-Code-compatible event JSON on stdin **(same shape kimi reuses)**" — kimi 确实是 snake_case(kimi_cli.py:568-570 注释只是关于 **kimi**),但 grok 不是;kimi 的形状不能外推给 grok。同一错误前提也写进了 CHANGELOG:22 和 CLI_REFERENCE:332。

**核实/兜底方式(复审重点 1 的答案)**:
- **核实**:`GROK_HOOK_DEBUG=1` 启动 grok,会把 hook stdin payload 打出来(二进制字符串实证);或 `/hooks` 模态的注解面板。
- **兜底(建议修复)**:在 `record_tool_event`(或 `record-tool` 入口做归一化)同时接受 camelCase:
  ```python
  tool = payload.get("tool_name") or payload.get("tool") or payload.get("toolName")
  session = payload.get("session_id") or payload.get("sessionId")
  ```
  改动极小、对 claude/kimi 零影响,并天然覆盖任何未来 camelCase 宿主。

## MAJOR

### MAJOR-2 心跳与错误可见性契约未满足(复审重点 4)

## NIT

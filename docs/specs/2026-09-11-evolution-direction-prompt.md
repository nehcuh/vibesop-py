## 二、要承接的研究结论（这是提案的出发点）

一项针对"AI 反复评审同一代码库、每次都能发现新优化点"的研究给出如下结论。**你要做的是把它映射到 VibeSOP 自己的架构上，而不是复述它。**

### 2.1 结论本体

观测到的"新发现"是四项之和：

```
真新发现（D 类规则违反 + T 类可检验问题：有限，几何衰减，最终趋近 0）
+ 改写型伪影（J 类主观建议 + 去重失败：无限，每轮大致常数）   ← 题眼
+ 修复引入的新发现（脉冲式）
+ 标准漂移带来的"新发现"（阶跃式）
```

只有当「问题集合有限可判定 + 评审确定性 + 上下文全覆盖 + 标准不漂移」四条**同时**成立，"再也发现不了新问题"才可能出现。四条在 LLM 评审语境下均不成立。

**所以：目标不是"消灭新增"，而是把「决策收敛」从「发现收敛」中解耦。**

### 2.2 关键映射（你已经能看到的三处强对应）

**对应一：VibeSOP 已经解决过一次这个问题，只解决了一半。**

`docs/dev/routing-benchmark.md` 记录的确定性层，已经具备完整的 D 类纪律：hermetic 六步中和全部机器相关输入、内容哈希指纹（排除 mtime 与绝对路径、CRLF→LF 归一）、退出码 0/1/3 语义、**吸收守卫**（`--update-baseline` 拒绝把 `ok1: true→false` 折叠进基线）、以及 2026-08-28 的确定性证明（`--update-baseline` 双跑 → 基线文件**逐字节相同**）。

**但同一份文档明确承认了一个盲区**，原文大意是：语义层（embedding、semantic_index embedding 回退、AI triage）以及 SCENARIO / INDEX 层**在 CI 里完全不可见**；门禁只覆盖 keyword / Levenshtein / explicit / TFIDF / fallback。

**这就是问题的形状**：确定性最强的部分被门禁覆盖得最好；而**非确定性最强的部分完全没有被观测**。这不是疏漏，是设计取舍——但取舍的代价目前没有被度量。

**对应二：产品命题与研究结论已经在同一句话上汇合。**

ROADMAP 当前方向是「**图书管理员先可信**」，且已改口「**找不到匹配是成功**」。
研究结论里最关键的一条是：**LLM 天然不敢说"没有"**（存在强制发射偏差——在"帮我找问题"的指令下，报"无问题"是高风险行为）。

**"找不到匹配是成功"与"敢说没有问题"，是同一个命题。** VibeSOP 已经把这句话写进了产品方向，但**还没有度量它**。

**对应三：禁止清单里已经有一条，正是研究结论的工程形式。**

ROADMAP 的禁止项含「**把 LLM 评审当放行闸**」。
但现状是：**它是一条写在文档里的禁令，不是机制。** 没有任何东西在检测"某条代码路径把 LLM 输出当成了门禁判据"。研究结论里的对应条目是：验证者与提出者同源时，验证环节在结构上失效。

### 2.3 现场证据（VibeSOP 自己就是标本）

- `.vibe/optimization-plan.md` / `-p1.md` / `-p2.md` / `-auto-opt.md`：**同一日生成的四份优化计划**，各自独立、无共享账本、无去重、无"是否收敛"判定。因此现在无法回答："第 4 轮相对第 1 轮，真实新增是增加了还是减少了？"
- 条目族示例：`P2-A1..A4` 是"给模块 X 补测试"、`P2-B1` 是"把 `_shared.py` 拆分"。**"给模块补测试""把文件拆分"在任何规模代码库上都不会自然终止**——这是 J/T 混合类。
- `.omx/artifacts/gate1..gate45+`：几十轮评审循环已经跑完，**从未被统计过**。
- `behavior_consistency` 的 0.5：正例对 = 0、负例对 = 1，脚本 fail-closed（exit 2）。**该状态已被如实记录**——这不构成缺陷指控，但它是一个明确的、可收口的缺口。

## 三、要求你产出的东西

一份设计提案，**至少**回答下列五个方向。**每个方向你都要么给出可行设计，要么明确论证"不该做"并说明理由。**

### A. 语义层的可靠性画像（填补被承认的盲区）

确定性层已被证明逐字节可复现；语义层在 CI 里不可见。

- **不要试图把语义层做成门禁**（违反 ROADMAP 禁令，且研究结论说它不可判定）。
- 取而代之：**把语义层当作一个分布来表征**。例如同一 query 在同一 commit 上重复 N 次，度量 top-1 命中的一致性。
- 你必须回答：用什么指标（提出具体定义）、N 取多少、如何避免把机器差异混入（复用既有 hermetic 六步）、产物落在哪、**它凭什么不是门禁**。
- 注意：既有 `tests/benchmark/routing_eval.yaml` 及 `_extended` / `_oneshot` / `_retention` 四个数据集已经存在，`routing_baseline.json` 已入库。**先确认可复用的量，不要假设要新建数据集。**

### B. 把「禁止 LLM 评审当放行闸」从声明变成机制

- 现状：文档禁令，靠人遵守。
- 你要回答：**什么样的机制能检测"LLM 输出被当作门禁判据"**？是测试、hook、还是静态检查？给出可落地的形式。
- 边界：不得因此扩大产品面；不得把 LLM 评审变成常驻默认注入（ROADMAP D4 已禁）。

### C. 优化循环的收敛度量（把历史变成数据）

- `.omx/artifacts/gate*` 与四份 optimization plan 是现成语料。
- 你要回答：**能不能在不新跑任何模型的前提下**，从这批历史里算出回调曲线与去重伪影比例？如果不能，缺什么、成本多少。
- 必须区分：哪部分结论是**观察性**的（存在选择偏差，例如那些 gate 的模型组合并非随机分配），哪部分才可能支持因果结论。

### D. no-match 率作为一等指标

- 产品命题已改为「找不到匹配是成功」，但没有任何度量在测 no-match 的发生率是否合理。
- 你要回答：**过度拒绝（本应命中却报 no-match）与过度命中（本应无匹配却硬塞一个）如何同时被观测**？既有 `must_not_inject` 负例类（见 `next-opt-design-v1.md` D3）是否已足够，缺什么？
- 关联：E1「弱模型路由质量（命中/拒判）」已在 W2 待办中。**说明你的提案与 E1 是什么关系**（是它的前置、替代，还是无关）。

### E. 产物持久化（一个已经发生的静默丢失）

- `.omx/` 在 `.git/info/exclude`；`.claude/` 在 `.gitignore`。**新写入这两个目录的文件会被静默忽略**——而 `.omx/` 下已有 356 个文件是历史强制入库的。
- 后果：一份新写的设计与实验记录，**不进版本控制，换机器即消失**。
- 你要回答：什么该跟踪、什么该忽略、如何让"我以为记录了"不再发生。给出具体方案（不要只说"建议规范"）。

## 四、硬约束

1. **不写代码。** 产出设计提案。若某方向确实需要先做小实验，在提案里写清实验设计，不要直接实现。
2. **不得突破冻结与禁令。** 严格对齐 `docs/ROADMAP.md` 的「禁止 / 冻结 / 撤回」清单与 `.omx/artifacts/next-opt-design-v1.md` 的 L1–L5。**不得扩张**：编排、市场、专家团、协同过滤、主动推荐。
3. **不得把 LLM 评审做成门禁或常驻默认注入。**
4. **每个主张都要能追到具体路径。** 引用必须给文件路径（或路径 + 行号）；**不得**凭印象描述代码行为。若你没有读到，就说没读到。
5. **严格区分证据等级**，并在提案中逐条标注：
   - **已实测**（有命令、有产物）——例如基线逐字节相同，是已记录的实测；
   - **有文档但未验证**；
   - **假设**（待实验判决）。
   这三级别**不得混写**。本项目已有「不以代理自述代替证据」的既有原则。
6. **不得编造任何数字。** 没有真实数据就写"待测"，并说明测法。
7. **必须包含可证伪的成功判据。** 每个方向给出「怎样算成功」与「什么结果会推翻它」。
8. **必须包含"不做什么"一节**，并说明为什么不。
9. **必须包含"我们不知道什么"一节**，列出你的提案所依赖的未验证前提。
10. 不做性能叙事对比（ROADMAP 已禁「为叙事跑墙钟时间对比」）。

## 六、最后的纪律

本项目有一句既有的约定：**「Verify before claiming completion」**（`CLAUDE.md`）。

你的提案里，凡是写着"已确认""可复用""现有能力足够"的地方，**必须能追到一次真实的读取**。
如果你没读到、没验证过，就写"未验证"。

**宁可交一份承认"有 N 处未核实"的提案，也不要一份看起来完整、实则凭印象拼成的路线图。**

## 附：这份提示词为什么长这样（给人看，不必给模型）

**它承接的研究结论只有一句可操作:** 把「决策收敛」从「发现收敛」里解耦。

**它之所以能用，是因为 VibeSOP 恰好是最理想的试验场:**

1. 你们**已经**在一个局部（确定性路由基线）做对了全部要点——hermetic 中和、内容指纹、退出码语义、吸收守卫、逐字节确定性证明。这是研究结论里"D 类可判定"的教科书实现。
2. 你们**已经**在同一份文档里承认了盲区（语义层在 CI 不可见）。所以"去度量它"不是引入新命题，而是**把已知缺口变成可观测**。
3. 你们**已经**在产品命题层面说出了结论（"找不到匹配是成功"）。所以这不是要你们转向，而是**要求你们把已经写下的原则变成数字**。
4. 你们**已经**有一条禁令（"禁止把 LLM 评审当放行闸"）。所以方向 B 不是新规，是**把已有的规则机制化**。
5. 你们**已经**有现场证据（四份同日优化计划、45+ 轮 gate）。所以方向 C 是**盘活既有资产**，不是新跑实验。

**换句话说：这个提示词不要求 VibeSOP 做新东西，它要求 VibeSOP 把已经做对的地方推广到已经承认没做的地方。**

这也正是研究结论的工程含义：**不要追求"没有更多问题"，要追求"决策可收敛"——而决策可收敛的前提，是你能把可判定的部分与不可判定的部分分开度量。**

## D2a near_miss ≥10 条

在 `routing_eval.yaml` 追加至少 10 条，字段建议：

```yaml
- query: <与某技能触发词形近但域外>
  expect: []
  category: near_miss
  subclass: near_miss
  note: near_miss of <skill-id>; 域外因为 <一句话>
```

用 `category: near_miss` **不要**用 `must_not_inject`。原因：must_not_inject 是 CI 硬闸，新近失例若当前过灌会让 `--update-baseline` 直接拒绝；提案本轮是观测。最低集五条保持 `must_not_inject` 不动。

近失要「形近但域外」，不要再写「今天天气怎么样」这种已经覆盖的明显负例。例子方向（可改，不要照抄如果与现网技能对不上）：

- 看起来像 code-review 但其实是在请人吃饭后写感谢信
- 看起来像 git 但在问 Git 这种动物
- 看起来像 session-end 但在说电视剧剧终
- 看起来像 TDD 但在问考试答题卡填涂

## D2b 生产聚合脚本

`scripts/aggregate_nomatch.py`：

- 读 `.vibe/observability/spans.jsonl`（`--spans` 可覆盖）
- 口径：`name` 以 `route:` 开头的 span（与 behavior_consistency 一致）
- 判定 no-match：span 上已有的 `has_match` / `primary` / `layer` 字段，能读到什么用什么；缺字段就 skip 并计数 `unscored`
- 输出窗口化（`--since` ISO8601，默认全部）：n_route / n_nomatch / rate / Wilson 95% CI（纯 stdlib，不准新依赖）
- 文件不存在 → exit 0 + JSON `{"error":"missing_spans","n_route":0}`（fail-soft，这是观测脚本）
- `--json` 打 JSON；默认人读一行

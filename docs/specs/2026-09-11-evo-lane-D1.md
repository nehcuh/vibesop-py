## 要做的事

在现有 metrics 上 **增加** 双向误差计数，report-only：任何新字段都不得把 `--hermetic --check` 从 0 打成 1。

定义（与提案一致，用现有 `result.has_match` / `ok1` 口径）：

| 字段 | 定义 |
|---|---|
| `n_pos` | `expect` 非空的条目数（skip `skipped_env`） |
| `n_neg` | `category == must_not_inject` **或**（`expect` 空且无 `reject` 的 no-match 断言） |
| `over_reject` | `n_pos` 里 `has_match` 为 False（本应命中却无 primary/real match） |
| `over_inject` | `must_not_inject`（或 `category == near_miss`）里 `has_match` 为 True |
| `no_match_by_layer` | 无 real match 的条目按「本应所在 layer」不好做；改为：有 match 的按 `layer` 计数 + `no_match` 计数。同时给 `no_match_rate = no_match / total` |
| `near_miss` 分层 | 若条目有 `subclass: near_miss` 或 `category: near_miss`，单独给 `n_near_miss` / `near_miss_over_inject`；没有就输出 0 |

把这些放进 JSON metrics（`--json` / `--json-out`）和人读 stdout（`--json` 关闭时多几行即可）。

**不要**因为这些数字非零而 return 非 0。`--check` / `--update-baseline` 路径保持原样。

`must_not_inject` 的 ok1 语义不准改。`near_miss` 条目若以 `category: near_miss` 出现，按负例计 over_inject，但 **不要** 把它加入 `--update-baseline` 的 must_not_inject 硬拒绝列表（那条列表继续只看 `category == must_not_inject`）。

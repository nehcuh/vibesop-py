# 论文与 VibeSOP：应结合，也应修正我们

[原文 v1](https://arxiv.org/html/2608.14036v1)：*Demystifying Agent Skills: Why They Work—Until They Don’t*，2026-08-14 预印本，普林斯顿等五校联合。

## 原文核验

- §5.1：65.7%“稳定执行”、4.5%“显式知识注入”是机制标注占比，非成功率；后者不专指私有知识。
- 表10：Skill 比 Workflow Memory 高6.06个百分点；比 Raw 高2.84个百分点，后者95%区间跨零。
- §5.5、表4、A.7：池从5增至100，实际使用precision从29.6%降至3.3%，分母是选用技能数；有用但非标准答案也算误选。任务成功率没有同步崩落。
- §3.2、A.1：Terminal-Bench 2/Pro、SkillsBench；Codex/GPT-5.3与Gemini CLI/Gemini-3.1-Pro-Preview；检索实验改用GPT-5.4。A.6仅测Codex来源向Gemini迁移，非全框架证明。
- §4、表3、A.2–A.3：238标签起于LLM，有独立人工核验；528配对三臂仍是LLM辅助，不能称全量人工盲标。
- §7、A.4：终端任务、有限模型；筛选过往同时有成功与失败的题，并重跑同题。跨任务泛化和开放协作仍有限。

## 对照两文：我们的推断

应把“技能只在设计/信息层有用”改成“技能可能补需求、补知识，也可能减少执行失误；是否增益要分场景验证”。“模型知道”不等于每次做对。论文挑战的是排他性结论，不能替我们证明因果。

R5只有单题单轮平分，不能排除可靠性增益。R6全程零读取，还有事后豁免，无法比较技能内容，更不能据22与23.5断言小模型追平大模型。R7评委方向相反，不是技能归零。R8盲评未结算，且相对R7换了任务书，不能把差异全归于需求粗细。

我们考社区方法卡；论文把同题历史经历提炼成技能。经验来源、题目、重复次数、评分方式不同，数字不可拼成同一条趋势线。

## 下一步建议（待验证）

1. PPT用一句话转折：“会做，不代表每次都做稳。”主讲一页，指标口径进附录。
2. 用同题比较无技能、历史记录、提炼技能；固定模型与预算，重复运行；另用未见题检验迁移。
3. 分开记录“选中、读到、适用、执行、验收”，同时看误触发、成功率、返工与成本；读取不等于有效。
4. 候选技能写清前提、反例、验证方法与来源成败；先修确定性放行闸，再试经验晋升。不要因论文正例恢复“每次都注入”。

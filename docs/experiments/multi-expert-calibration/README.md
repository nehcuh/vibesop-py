## 校准修正 1：推理模式（首批运行后、第二批之前）

首批出现 `finish_reason=length`，若干响应的 completion tokens 全部是 reasoning tokens、content 为空。官方文档确认默认开启 high 推理，且 thinking 模式会忽略 temperature；因此首批的 temperature=0 只是请求参数，并非已生效的确定性控制。第二批统一显式 `thinking.type=disabled`，保留同一任务、分配与预算，仅作执行器校准，不能与第一批合并或挑最好结果。

官方定价页还确认旧 `deepseek-v4-flash` 名称已被重定向到 **DeepSeek-V4.1-Flash**，响应为 `deepseek-flash`。所有记录均保留请求与响应名称；不可将本批报告成旧版 V4 Flash 或可固定权重的模型快照。

来源（2026-09-13 核对）：[推理模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[模型与定价](https://api-docs.deepseek.com/quick_start/pricing/)。当前 Flash 每百万 token 非高峰价：缓存命中输入 $0.003、未命中输入 $0.15、输出 $0.6。仅按实际 usage 估算，不冒充账户账单；本次周日处于非高峰。

## 校准修正 2：内部报告截断与最终交付分开处理

第二批暴露执行器判定错误：C/D 的 400-token 交流报告被截断时，runner 将整次运行直接判错，即使总体预算尚有余额。这并非“全程预算耗尽”。第三批在相同任务、顺序、模型模式和额度下，保留截断的内部文字并让后续阶段继续，单独记录 `partial_internal_stages`；最终代码交付/检查输出仍必须完整且可解析。非 length 的服务错误仍中止。三批全部留存，第三批不覆盖前两批，亦非新增正式样本。这是修复执行器过早终止，不能说模型质量被提升。

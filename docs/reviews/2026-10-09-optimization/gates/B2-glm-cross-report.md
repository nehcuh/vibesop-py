## Ranked findings

1. **[P3 — cost observation, no action required]** Steady-state deep-check cost rose with content addressing. `_should_check_reload` now runs both `_compute_skill_mtimes` (all markdown) and `_compute_paths_hash` (full byte read of every md/yaml input + registry rglob + deep auto-config rglob): ~180 ms per 5s per active router on this repo's 4.5 MiB universe (was a stat-only SKILL.md walk in parent, ~66 ms class). Per-route hot overhead stays 0.065 ms and the window skips it entirely, and on a small end-user universe the deep check measured 3.3 ms. This is the deliberate price of the same-mtime correctness fix (D05); if it ever matters, a (path, mtime, size)-keyed hash memo with an explicit same-mtime+same-size acceptance note would recover most of it. Not a blocker.
2. **[P3 — minor over-invalidation]** `_cached_reload_locked` always bumps the index epoch and clears parsed loader caches, including on a pure disk-cache hit where nothing changed (e.g. first fill). Worst case is one extra index JSON reload (~1 MB parse) per router construction; failure direction is extra work, never staleness. Acceptable.
3. **[P3 — pre-existing, unchanged by this patch]** `filter_routable`'s `DEPRECATED` warning branch is unreachable because `SkillLifecycleManager.is_routable` is ACTIVE-only and `continue`s first (verified live: deprecated skill stays in the discovery pool but is unroutable). Register for a future cleanup; out of B2 scope.
4. **[Info — declared semantics confirmed]** SKILL.md body edits inside the armed 5s window are served stale by design (asserted by the patch's own tests); governance mutations (enabled/scope/lifecycle/owner-hash) are visible on the very next route. This matches the roadmap's product decision ("governance must be visible on the next route; the deep walk stays on the 5s interval").
5. **[Info — register-only debt preserved]** `core/config/manager.py` `load_registry` in-memory cache remains untouched and is registered audit-only in `_registry_files`' docstring, exactly as the plan requires. `external_loader`/`_layers` siblings were actually fixed (epoch + `clear_cache`) rather than merely registered — stronger than the plan minimum.

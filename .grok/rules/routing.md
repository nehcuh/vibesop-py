# VibeSOP Routing Protocol

> **Generated by VibeSOP** — Grok Build native adapter
> **Always Loaded**: Applies to every session

## Mandatory Routing

**Before every non-trivial task, call `vibe route` to find the best skill.**

```bash
vibe route "<user_request>"
```

Then read the matched skill's `SKILL.md` and follow its instructions.

## How It Works

1. You type a request in Grok Build.
2. The `vibesop-route` hook intercepts it via `UserPromptSubmit`.
3. `vibe route` matches the best skill from available skills.
4. The skill's instructions are injected into your context.

## Agent Runtime Rules

### [ACTIVE SKILL: xxx]

1. Read the skill's `SKILL.md` file
2. Follow the skill's steps exactly — do not skip
3. Report completion using the skill's defined marker

### [EXECUTION PLAN] injected

1. Follow steps in order
2. Read each step's `SKILL.md` before executing
3. Report progress: "Step N complete"
4. Wait for dependencies before starting dependent steps
5. Parallel steps may run simultaneously

### [EXPLICIT SKILL: xxx]

User explicitly requested a skill. Load and follow it immediately without routing.

## Routing Confidence

- **Auto-select**: Confidence >= 0.6
- **Manual select**: Confidence < 0.6 (top 3 candidates shown)
- **Fallback**: No match → `FALLBACK_LLM` layer with explanation

## Supported Commands

| Command | Purpose |
|---------|---------|
| `vibe route "<query>"` | Match best skill for a query |
| `vibe skills list` | List installed skills |
| `vibe doctor` | Check environment health |
| `vibe build --platform grok-build` | Deploy routing hooks and rules |

## Session Lifecycle

When the user signals session end ("that's all", "收工", `/session-end`, etc.),
run `session-end` to flush session state.

For full documentation: read `docs/architecture/routing-system.md` in the VibeSOP project.

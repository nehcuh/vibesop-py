# 验收结果 — 对照需求与产物

本技能只在用户显式选择或编排器选中时使用，不参与自然语言自动路由。

只做验收。不要改实现，不要运行未获授权的部署，不要把计划标成完成，不要自动调用其他代理。

## 1. 收集材料

读取三样东西，缺一不可：

- 原始需求：用户原话、规格、验收清单
- 产物：代码、文档、分析结论、部署结果等实际输出
- 机器记录：测试输出、命令结果、扫描日志、构建记录、文件状态

没有读到的材料不能用想象补。

## 2. 按任务类型选检查方法

- **代码**：跑相关测试，对照行为是否符合需求；看失败输出，不凭感觉。
- **文档**：检查章节是否齐全、声明是否有来源；缺出处要标出。
- **分析**：核对数据和计算步骤是否可复算；抽查关键数字。
- **部署**：只在已有授权下查看实际状态（进程、接口、发布记录）；没有授权就不要部署。

任务类型不明确时，先按需求里写明的类型处理；仍不清楚则标 blocked，并写缺什么信息。

## 3. 判定

每一项需求单独判定：

- **blocked**：缺证据（没跑到测试、没读到产物、没有授权查看部署状态、来源缺失）
- **failed**：有证据且证据表明未满足需求
- **passed**：清单上每一项都有对应证据，且证据支持满足

默认不得通过。模型自己说「看起来没问题」不能代替证据。

## 4. 分别记录两类结论

报告里分开两栏，不要混写：

- **机器验收**：命令、测试、文件、状态查询的实际输出（引用路径或摘要）
- **模型评审**：对完整性、清晰度等无法单靠机器判定的判断；必须标明这是评审意见

模型评审不能把 blocked 或 failed 改成 passed。

## 5. 禁止事项

- 修改被验收的实现
- 运行未获授权的部署或发布
- 把计划或任务标为完成
- 用代理自述顶替测试输出或状态查询
- 自动召唤其他代理去「帮忙修」或「帮忙确认」

## 退出条件

- [ ] 已读取原始需求、产物和机器记录
- [ ] 已按任务类型执行对应检查
- [ ] 每项需求都有 passed / failed / blocked，并附证据
- [ ] 机器验收与模型评审分开记录
- [ ] 未改实现、未擅自部署、未标记计划完成
